## 2. Перечень используемых инструментов и обоснование выбора

- **Python 3.11+** — основной язык для написания автотестов; широкая экосистема библиотек и поддержка CI.
- **pytest** — фреймворк для запуска тестов; поддержка параметризации, фикстур, гибкой структуры.
- **Allure Report** — генерация наглядных отчётов по результатам прогонов; интеграция с pytest.
- **Selenium WebDriver / Playwright** — автоматизация действий в браузере; выбор зависит от требований к стабильности и скорости.
- **Docker** — контейнеризация тестового окружения; воспроизводимость среды на разных машинах.
- **Git + GitHub** — контроль версий, хранение кода и артефактов.

## 3. Перечень и описание возможных рисков при автоматизации

| Риск | Описание | Вероятность | Влияние | Меры по снижению |
|------|----------|-------------|---------|------------------|
| Частые изменения UI | Верстка и элементы страницы могут меняться, что приведёт к падению тестов | Высокая | Высокое | Использование Page Object Model, стабильных локаторов, ревью изменений |
| Нестабильные тесты (flaky tests) | Тесты могут падать из‑за таймаутов, гонок условий, асинхронности | Средняя | Среднее | Явные ожидания, повторные попытки, изоляция окружения |
| Проблемы с CI/окружением | Нехватка ресурсов, ошибки сборки, проблемы с сетью | Низкая | Среднее | Локальные прогоны перед пушем, логирование, мониторинг пайплайна |
| Недостаток тестовых данных | Отсутствие валидных данных для сценариев | Средняя | Среднее | Подготовка фикстур, мокирование API, использование тестовых аккаунтов |

## 5. План сдачи работ

| Этап | Срок (от начала работы) | Результат |

## 6. Отчёт по автоматизации

Отчёт формируется в виде файла `Plan.md` и хранится в репозитории проекта. По итогам выполнения работ будут добавлены:
- `allure-results/` — результаты прогонов (не коммитятся в git, но генерируются при каждом запуске).
- `reports/` — скриншоты, логи, примеры отчётов Allure (HTML).
- Обновлённый `README.md` с инструкцией по запуску тестов и интерпретации отчётов.
